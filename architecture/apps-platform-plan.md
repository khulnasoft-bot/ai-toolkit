# Implementation Plan — `apps/docs`: AI SDK–class documentation platform

**Status:** Proposed (supersedes the `apps/*` topology portion of ADR-005 with concrete detail)
**Scope:** `apps/docs` only. `apps/www` and `apps/studio` are deferred to later phases.
**Date:** 2026-10-08

---

## 1. Goal

Stand up a public documentation platform for the AI TOOLKIT that matches the
capabilities of ai-sdk.dev: versioned MDX docs, provider/model/tool/gateway catalog,
API playground, `llms.txt`, and search — all generated from the canonical `content/`
tree and the existing `@ai-toolkit/platform` registry, with **zero** duplicated content
and **zero** dependencies from `packages/*` onto `apps/*`.

## 2. Starting state (verified)

| Asset                                          | State                                                                                                                      | Note                                                                 |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `content/`                                     | 455 `.mdx`, only frontmatter keys `title`, `description`, `tags`, `collapsed`                                              | canonical source                                                     |
| `content/gateways-registry/registry.ts`        | 8 gateways                                                                                                                 | compiled per `.gitignore` rule                                       |
| `content/tools-registry/registry.ts`           | 13 tools                                                                                                                   | ditto                                                                |
| `build/platform-registry.json`                 | 443 records (128 provider, 187 model, 8 gateway, 13 tool, 22 template, 85 recipe), 289 KB, git-tracked, **zero consumers** | generated by `pnpm platform-registry`                                |
| `packages/foundation/platform`                 | `PlatformRegistry`, `validateRegistry`, `createPlatformApi`                                                                | `private: true`, `stability: internal`, no importers                 |
| `apps/`                                        | does not exist                                                                                                             | `pnpm-workspace.yaml` glob is `- 'apps'` (bare dir, matches nothing) |
| `.eslintrc.js`                                 | `settings.next.rootDir: ['apps/*/']`                                                                                       | points at a nonexistent dir                                          |
| `tools/scripts/validate-structure.mjs:290-400` | fully-written docs mirror validator (coverage + freshness)                                                                 | currently a no-op because `apps/docs/content` is absent              |

The mirror transform is already specified and implemented in `validate-structure.mjs`;
the plan adopts it verbatim as the codegen contract rather than inventing a second one:

1. strip `^\d+-` from every path segment
2. drop the leading H1 (title renders from frontmatter)
3. rewrite fence metadata: `filename=`→`title=`, `file=`→`filename=`, `highlight="N"`→`{N}`, `env`→`dotenv`
4. drop site-only `<span id="…" />` anchors
5. site-only files allowed: `**/meta.json`, `docs/elements/**`

## 3. Target architecture

```
content/**.mdx                    (canonical, edited by humans, never generated)
        │  pnpm docs:mirror  (new: tools/scripts/mirror-docs.mjs)
        ▼
apps/docs/content/**.mdx + meta.json   (derived, git-tracked, coverage-checked)
        │
        ├─► Geistdocs / Next.js App Router → https://studio.khulnasoft.com/docs
        └─► build/platform-registry.json ─► /api/platform/v1/*  (createPlatformApi)
```

Dependency direction (ADR-008 compliant): `apps/*` → `packages/*` only.
`apps/docs` depends on `@ai-toolkit/platform` and `@ai-toolkit/elements|design`;
`packages/*` must not reference `apps/*` (already enforced by
`tools/scripts/check-dependency-direction.mjs`).

### 3.1 Why a build-time mirror, not a runtime read of `content/`

Geistdocs resolves content relative to its own directory and expects site-format
filenames and nav metadata. Reading `content/` directly would require either a
runtime resolver shim (breaks SSG/prerender and `next` output tracing) or duplicating
nav config. The mirror keeps the site conventional and lets the existing freshness
check catch drift in CI. `content/` remains the single source of truth, and stays
shippable inside the published packages via their existing prepack scripts.

## 4. Phase breakdown

### Phase 0 — Workspace topology (blocked-by nothing)

1. `pnpm-workspace.yaml`: change `- 'apps'` → `- 'apps/*'`.
2. Create `apps/docs/package.json`:
   - `name: "@app/docs"`, `private: true`, `version: "0.0.0"`
   - `stability: "internal"`, `owners: ["@khulnasoft/ai-toolkit-core"]` (ADR-007)
   - deps: `next@16.3.6` (match root), `react@19.0.0-rc-*`, `geist` (Geist Sans/Mono, DM Sans), `@ai-toolkit/platform: workspace:*`, `@ai-toolkit/elements: workspace:*`, `@ai-toolkit/design: workspace:*`
   - scripts: `dev`, `build` (`pnpm docs:mirror && pnpm --filter @ai-toolkit/platform generate-registry && next build`), `start`, `lint`, `type-check`, `prettier-check`
   - no `publishConfig`, excluded from changesets (matching the ADR-005 exclusion rule)
3. `turbo.json`: `docs:mirror` task with `outputs: ["content/**"]`; add `GEISTDOCS_*` env already present in `build` env list.
4. `.gitignore`: no change needed (`.next`, `node_modules` already covered).
5. Verify: `pnpm validate-structure` passes with the empty `apps/docs` tree and does not error on the missing mirror.

**Exit:** `pnpm install` resolves `@app/docs`; `turbo build --filter=@app/docs` is wired.

### Phase 1 — Mirror codegen (`tools/scripts/mirror-docs.mjs`)

Single script, no deps beyond Node, run via `pnpm docs:mirror` at root and from
`apps/docs` `prebuild`.

- Read `content/{docs,cookbook,providers}/**/*.mdx`.
- Apply the five transform steps from §2.
- Resolve the two numbering collisions that exist today, deterministically:
  `content/docs/02-foundations` + `02-getting-started` and `03-agents` + `03-ai-toolkit-core`.
  Fix at the source by renumbering `content/` to a unique sequence **in Phase 1**, then the
  mirror needs no special-casing. (Renumbering `content/` is a content-only change; prefix
  values are ordering hints and carry no route semantics.)
- Emit `apps/docs/content/**/meta.json` for every section and page directory, generated from
  the numeric prefixes + frontmatter `title`/`description`. `collapsed: true` maps to
  `"collapsed": true`; `tags` maps to `"tags": [...]`.
- Rewrite site-route links found in bodies: `/docs/reference/ai-toolkit-core/*` and
  `/providers/ai-toolkit-providers/*` already match post-strip paths; relative
  extension-less links resolve naturally. Replace `__PROVIDER_IMPORT__;` and
  `model: __MODEL__,` tokens via a docs-only MDX remark plugin (Phase 3), not codegen.
- Idempotent, `--check` mode that exits non-zero when the tree is stale (for CI).

**Exit:** `pnpm docs:mirror && pnpm validate-structure` is green; re-running produces no diff.

### Phase 2 — Site shell

- `apps/docs/app/{layout,page,not-found,error}.tsx`, `next.config.ts`, `tsconfig.json`
  (extend root, `references` to the workspace packages it consumes — run `pnpm update-references`).
- Geistdocs scaffold: `content/docs`, sidebar from `meta.json`, top nav tabs
  **Docs / Providers / Cookbook / API Reference / Studio**.
- Global layout: sticky sidebar with search input, `TableOfContents` from `##` headings,
  prev/next pagination from sibling order, footer with KhulnaSoft links, dark-mode toggle.
- Import MDX components used by the corpus. Measured usage counts from `content/`:
  `Check` 1422, `Snippet` 555, `Cross` 550, `Note` 534, `Tab` 425, `Tabs` 110,
  `PropertiesTable` 106, `IndexCards` 13, plus `Support`, `OfficialModelCards`,
  `CommunityModelCards`, `ExampleLinks`, `GithubLink`, `Browser`.
  Implement as `apps/docs/components/` (thin wrappers over `geist` + `@ai-toolkit/design`
  tokens), with the same names so no body edits are needed. `Check`/`Cross` are
  capability-matrix cells — style them as accessible icons with `aria-label`.
- `docs/elements/` site-only section (ai-sdk.dev parity) rendering
  `@ai-toolkit/elements` docs; allowed as site-only by the validator.

**Exit:** all 455 mirrored pages render; `next build` emits zero MDX errors.

### Phase 3 — MDX plugin for provider/model tokens

`apps/docs/mdx-plugins/resolve-tokens.ts` (remark):

- `__PROVIDER_IMPORT__` → `import { <provider> } from '@ai-toolkit/<provider>'`, derived from
  the page's provider section or an explicit `provider=` frontmatter key added to the
  provider MDX files in `content/providers/**`.
- `__MODEL__` → the page's default model id, from the same frontmatter key.
  Both require a small additive frontmatter change to ~43 provider pages; frontmatter is
  already validated, so add the keys to the content contract, not ad hoc.

**Exit:** no `__TOKEN__` remains in any built HTML.

### Phase 4 — Registry-backed catalog + API

1. Make `@ai-toolkit/platform` consumable by an app: it is `private: true`, which is fine for
   `workspace:*` linking (no publish), but drop `private` if the package is ever to ship.
   Add `apps/docs` → `@ai-toolkit/platform` to the dependency graph.
2. Route handler `apps/docs/app/api/platform/v1/[[...path]]/route.ts` — thin adapter:
   ```ts
   const handle = createPlatformApi(new PlatformRegistry(snapshot));
   export async function GET(req: NextRequest) {
     const url = new URL(req.url);
     const res = await handle({
       pathname: url.pathname,
       searchParams: url.searchParams,
     });
     return Response.json(res.body, {
       status: res.status,
       headers: res.headers,
     });
   }
   ```
   Runtime-neutral by construction (ADR-004): no Node builtins, no `fs` in the handler —
   import the JSON snapshot directly so bundlers inline it.
3. `pnpm platform-registry` must run before `next build`; add it to the app `build` script
   and add a `registry` turbo task with `outputs: ["../../build/platform-registry.json"]`.
4. Static catalog routes generated from the same snapshot (no HTTP hop at build time):
   - `/providers/ai-toolkit-providers/[slug]` — 42 pages, install tabs from
     `installCommand`, capability matrix from `capabilities`
   - `/providers/gateways/[slug]` — 8 pages
   - `/tools/[slug]` — 13 pages
   - `/models` — 187 model rows grouped by provider, filterable
   - `/examples` — 22 templates from `examples/registry.json`
   - `/cookbook` — 85 recipes
5. Cross-link every MDX page to its registry record via `source.path` so the docs and the
   catalog cannot diverge silently.

**Exit:** `curl /api/platform/v1/catalog/providers` returns 128 records with
`x-platform-registry-version: source-baseline-v1`; all catalog routes prerender.

### Phase 6 — CI, quality gates, deploy

- `.github/workflows`: add a `docs` job — `pnpm install` → `pnpm docs:mirror --check` →
  `pnpm validate-structure` → `pnpm arch:validate` → `turbo build --filter=@app/docs`.
- Playwright smoke test (`examples` already use `@playwright/test`): load 3 representative
  pages, assert sidebar nav renders and `/api/platform/v1/search?q=openai` returns records.
- `vercel.json`: add the docs project; confirm `studio.khulnasoft.com/docs` routing.
- Changeset policy: apps are excluded; only `content/**` edits trigger changesets, and
  `content/` ships inside packages so existing prepack flows cover it.

## 6. Risks

| Risk                                                                                                                                                         | Mitigation                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Prefix collisions (`02-`×2, `03-`×2, plus collisions inside `09-troubleshooting`, `07-reference/01`, `01-ai-toolkit-providers`) make sidebar order ambiguous | Renumber `content/` once in Phase 1; mirror emits explicit `meta.json` so order never depends on filename sorting afterwards |
| Geistdocs couples to its own content layout, so future framework upgrades are costly                                                                         | Isolate all coupling in `apps/docs/content` + `lib/nav.ts`; MDX components are ours, not Geist's                             |
| 455-page prerender is slow                                                                                                                                   | Route-level static generation + `next build` cache; catalog routes are data-driven and cheap                                 |
| `__PROVIDER_IMPORT__`/`__MODEL__` tokens need provider frontmatter the corpus lacks                                                                          | Add keys in Phase 3 as a scripted one-time migration over `content/providers/**`                                             |
| `@ai-toolkit/platform` is `private: true` + `stability: internal`                                                                                            | Legal for `workspace:*`; document that apps may depend on internal packages but must not publish                             |
| Registry snapshot is generated and could be stale in CI                                                                                                      | Make `registry` a declared turbo input/output and run generation in the CI `docs` job                                        |

## 7. Definition of done

- `pnpm docs:mirror --check` exits 0 (no drift between `content/` and `apps/docs/content/`).
- `pnpm validate-structure`, `pnpm arch:validate`, `pnpm arch:capabilities:check` all pass.
- `turbo build --filter=@app/docs` succeeds; every one of the 455 pages plus all catalog
  routes is present in the build output manifest.
- `/api/platform/v1/{search,metrics/overview,catalog,catalog/providers,catalog/models,catalog/gateways,catalog/tools,catalog/templates,catalog/recipes}`
  responds with `cache-control`/`etag`/`x-platform-registry-version`.
- `/llms.txt`, `/llms-full.txt`, `/sitemap.xml`, `/robots.txt` served.
- No `packages/*` → `apps/*` edge introduced; `.eslintrc.js` `next.rootDir` now resolves.
- Docs deploy and are reachable at the `homepage` URL in root `package.json`.

## 8. Suggested sequencing

Phases 0→1→2 are strictly sequential and deliver a working docs site. Phase 3 can run in
parallel with Phase 2's component work. Phases 4→5→6 are sequential after 2.
Total effort estimate: Phase 0 ~0.5d, Phase 1 ~1.5d, Phase 2 ~4d, Phase 3 ~1d,
Phase 4 ~2d, Phase 5 ~5d, Phase 6 ~1.5d.
